# 安全名用 `_@_` 连接 owner 和 repo

技能来源在技能库里的目录名，是把 `owner/repo` 里的 `/` 换成 `_@_`：`mattpocock/skills` 装进 `mattpocock_@_skills`。

## 为什么

这样目录名可逆。`_` 单下划线是参考实现 `agent-manager` 的做法，但它不可逆：`mattpocock_skills` 到底是 `mattpocock/skills`，还是有人手工建的一个叫 `mattpocock_skills` 的本地来源，从名字上分不出来。而「技能以磁盘为准」（ADR 0001）要求磁盘能自己说清每个来源是谁，所以目录名必须能读回来。

`_@_` 在 GitHub 的 owner/repo 字符集（字母、数字、`.`、`_`、`-`）里不会自然出现，因此不会和名字本身撞车。

## 后果

- 目录名已经是这个形状，换规则要迁移用户磁盘上已有的技能库。
- 手工建一个不含 `_@_` 的目录，会被当作本地来源（没有仓库），而不是报错。
