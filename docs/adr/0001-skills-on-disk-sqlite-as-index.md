# 技能以磁盘为准，SQLite 只做索引

已安装的技能以 `~/.viva-agents-manager/skills` 下的目录为唯一权威，`~/.viva-agents-manager/sqlite.db` 只存由此派生的索引，以及磁盘表达不了的状态（启用等，后续再加）。

## 为什么

安全名可逆（`owner/repo` ↔ `owner@repo`），所以目录树本身已经完整表达了「哪个来源装了哪些技能」。反过来让数据库权威，就得维护一份磁盘镜像，而镜像会漂移：手工删掉目录、改掉 `SKILL.md`、或者改名和落盘之间崩溃，树里都会继续列出不存在的东西。索引每次从磁盘重建，就不存在说谎的窗口。

## 考虑过的替代

- **数据库权威 + 磁盘镜像**：参考实现 `agent-manager` 的做法（`skill_sources`/`skills` 是目录，`skills/` 是镜像）。需要额外的对账与回滚逻辑，且崩溃窗口无法消除。
- **纯磁盘扫描，不建表**：更小，但每次列出来源都要读一遍所有 `SKILL.md`，且没有地方放后续「启用」这类磁盘表达不了的状态。

## 后果

- 运行期间手工往技能库里丢文件夹，要重启才看得到。
- 数据库打不开时退化成内存 store，窗口照开：它只是索引，不该让应用起不来。
- 索引的刷新时机只有两处：启动一次，每次安装成功后一次。

启用状态的存储决策已由 [ADR-0003](0003-enablement-from-symlinks.md) 取代：实际软链可以表达启用状态，无需存入数据库。

[ADR-0006](0006-manual-skill-expiration.md) 增加独立保存的过期标记：它是用户元数据，不能随派生索引重建或删除。
