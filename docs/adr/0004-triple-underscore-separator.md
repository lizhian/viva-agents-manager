# 安全名与启用软链统一使用三下划线分隔

为使名称更简洁，使用 `___` 替代旧分隔符；来源 `owner/repo` 对应 `owner___repo`，启用软链对应 `vam___owner___repo___skill`。这取代 ADR-0002 的分隔符选择，并更新 ADR-0003 的软链命名，启用状态仍以实际软链为准。

三下划线可能出现在原始名称中，因此把它作为保留分隔符：来源和技能原始名称不能包含它。还拒绝会与分隔符相连而产生歧义的边界下划线（owner 末尾、repo 开头或末尾、技能开头、本地来源开头或末尾）；例如 `a_/b` 与 `a/_b` 都会生成 `a____b`。不会改写来源或技能原始名字来规避这些限制。

启动时迁移旧来源目录及指向该技能库的旧受管软链，再重建 SQLite 索引，保持启用状态。先检查目标冲突，再创建新链接、移动来源目录、删除旧链接；中断后可重试。冲突时不覆盖已有内容，启动返回具体错误，由现有日志路径报告；每个来源单独迁移，已完成的来源不会回退。其他应用的文件或软链不迁移。

本决策已由 [ADR-0005](0005-at-separator.md) 取代，当前统一使用单个 `@`，不再限制下划线。
